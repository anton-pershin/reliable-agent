## AC3 repeatability on the default profile

**Status**: active

### Objective

Make project acceptance criterion AC3 (`VM4 <= 0.05`) accepted on the authoritative `default` profile, while preserving the constitution's task-success, sampling, budget, and general-purpose-reasoning requirements. See [constitution](../constitution-spec.md), especially FR1, NFR1, NFR4, NFR5, P8, and P11.

### Current constraints

- Use `openai:qwen/qwen3.5-9b` for all validation experiments, as directed by the user on 2026-11-18. Alternative model sizes are out of scope.
- Use only the self-hosted A10 deployment. The user subsequently decided that provider-hosted results are misleading and must be ignored; Caila runs are retained only as excluded experiment history, never as candidate evidence.
- Use general-purpose model reasoning over public tasks, observations, action descriptions, and results; no benchmark-specific solver or private evaluator data.
- Use default model sampling as required by constitution preference P11; do not make episodes exact replicas through fixed-seed or deterministic-serving restrictions.
- Keep every episode within 50 action attempts and 300 seconds.
- Use the running dedicated A10 efficiently. Prefer partial configurations containing only unperturbed episodes and inexpensive criteria; avoid AC2/AC4/AC5 experiment populations unless needed for a final regression check.
- Partial validation is diagnostic. Only an unchanged full `default` run can certify project-level AC3 acceptance.

### Current state

The current `main` implementation (`1bd6081`) has the spec 04 planning mechanisms. Full `default` run `20261114T053703-525279Z-b864ae241134` used solution commit `c3e5a94` and produced VM1 = 0.67 and VM4 = 0.15. The newer full run `20261117T150114-324103Z-9acb73d41f31` used commit `b490da1` with the same agent settings and produced VM1 = 0.665 and VM4 = 0.25. AC3 therefore remains valid rather than accepted, with substantial run-to-run variation even on the dedicated runtime.

An early three-repeat screen of revision `e0847c3` produced VM4 = 0.04999999999999993 with VM1 = 0.5667. This was a screening observation, not sustained AC3 evidence, and is superseded by completed 10-repeat results. Its 10-repeat extension was early-stopped when repeat 1 had 9 successes and repeat 2 reached 11, making VM4 >= 0.10 unavoidable.

H=2 on `fdbf61a` improved self-hosted VM1 to 0.6333 and reduced screening time from 50 to 40 minutes, but its three-repeat VM4 was 0.15. Adding goal regression at H=2 kept VM1 at 0.6333 and increased VM4 to 0.20.

Provider-hosted runs were stopped and excluded after the user determined that their results are misleading; they play no role in candidate selection or acceptance. Self-hosted A10 H=1 goal regression completed with VM1 = 0.6333 and VM4 = 0.10, so it was not extended.

The targeted optimized/budget H=1 goal-regression run scored repeat rates 0.50, 0.75, 1.00 on the four tasks, producing VM4 = 0.50 despite VM1 = 0.75. It did not justify an optimized full extension. The final original-candidate 10-repeat attempt was early-stopped after repeats of 0.65, 0.65, and 0.60 because its computed range was strictly rejected. A subsequent request explicitly required a complete 10-repeat test of the best candidate. Run `20261118T151459-848922Z-5228d0ade946` therefore used the same H=1 goal-regression configuration and original self-hosted runtime without early stopping. All 200 episodes completed in approximately 2 h 28 min: repeat rates were 0.45, 0.50, 0.45, 0.65, 0.65, 0.65, 0.60, 0.55, 0.55, 0.55; VM1 = 0.56 and VM4 = 0.20. AC6 and AC7 were accepted.

The implementation provides engineering artifacts—race-independent prefix voting, independent vote/execution horizons, empty-plan control, and 114 passing tests—but **no demonstrated 10-repeat VM4 improvement**. Earlier three-repeat screens are retained only as superseded screening observations. Spec 06's AC6 and AC8 remain unmet; the branch is not represented as an accepted or integration-ready project implementation.

A complete trace analysis of C18 on 2026-11-19 found that 78 failures ended in time exhaustion, nine were false completions, and one hit the retained-output limit. Exact repeated `(public observation, action)` attempts occurred in 71/78 timeouts. Six of nine false-completion rationales explicitly said that the goal was not satisfied despite the accepted boolean verdict. Several mixed-task failures sampled 3–5 valid complete plans initially but discarded those tails under H=1 execution and derailed during later votes. These observations motivate a different candidate: vote on the first action but retain and execute the selected complete plan, suppress observed-transition cycles, require independent completion-verifier consensus, and omit provider seeds explicitly.

The legacy model client always sent its configured seed (default 0), even though serving was not deterministic. New candidate runs will enable `--free-sampling`, which omits the provider seed on every request and retry. Historical runs remain useful observational baselines but are not evidence for the revised candidate. The combined candidate is experimental; no performance improvement is claimed before a completed 10-repeat run.

### Current understanding

#### Supported by evidence

- Whole-plan votes often collapse to lowest-sample-index tie breaking because long sampled plans rarely agree, while first actions have a much stronger mode (spec 04 and methods report).
- Prompt-only short horizons were not followed reliably; plan and goal reviews did not saturate weak-task success.
- Provider-latency instability inflates VM4. The current dedicated self-hosted runtime removes that confounder, leaving per-task model sampling noise.
- Engine-enforced one-action prefixes with full-plan prompts produced a three-repeat range of 0.05 and suppressed 68 empty candidates, but this short-screen signal did not establish a 10-repeat improvement.

#### Tentative or unresolved

- No tested self-hosted configuration sustained VM4 <= 0.05 over 10 repeats. Whether a general-purpose mechanism can saturate the remaining stacking flips without changing the model or sampling remains unresolved.
